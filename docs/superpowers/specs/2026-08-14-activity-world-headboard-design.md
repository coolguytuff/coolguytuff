# Aaron Profile Activity World + Headboard Design

## Status

Approved for implementation by the user on 2026-08-14. This spec extends the existing Dave Command profile without replacing its established visual system.

## Objective

Make the top half of the GitHub profile substantially more memorable while preserving readability and GitHub-native reliability. The profile should feel like a cohesive animated command interface, not a pile of widgets.

The new hierarchy is:

1. animated identity headboard
2. Dave Command Core
3. animated contribution Activity World
4. existing profile sections, moved down and renumbered coherently

The new Activity World must use the user's real public contribution pattern as its terrain source and feature an original animated traversal character whose locomotion changes according to the terrain.

## Hard platform constraints

- Everything visible must render directly on the GitHub profile README.
- No JavaScript, WebGL, iframe, canvas, or separate interactive site is required or used.
- Animation is implemented with SVG/SMIL and SVG-safe CSS only.
- Primary visuals are self-hosted in the repository.
- The README must remain easy to read when motion is ignored.
- Dave remains the flagship visual and project immediately below the identity headboard.
- Existing privacy boundary remains: Dave is described only at a high public level; no private repository link, personal email, school, age, exact location, or other unnecessary personal details are exposed.

## 1. Identity headboard

Replace the plain Markdown name block with `assets/identity-headboard.svg`, a full-width 1200px command marquee.

### Composition

- Large centered `AARON SLUTSKY` lettering is the dominant element.
- `@coolguytuff` sits beneath it in a smaller monospaced/operator line with separate spacing and tone.
- Supporting line remains concise: `AI SYSTEMS // AUTONOMOUS AGENTS // AUTOMATION // EXPERIMENTAL SOFTWARE`.
- Background uses the existing Dave palette: near-black/navy, cyan, electric blue, violet, restrained magenta.
- Dimensional lettering uses layered outlines, offset shadows, scanline highlights, and animated edge sweeps to create depth without hurting legibility.
- The headboard uses subtle moving grid/radar lines and sparse particles, not constant visual noise.

### Easter eggs

Two tiny, infrequent, stylized pop-up cameos are allowed inside/behind the name geometry:

- a simple yellow sponge-like face/silhouette nod
- a teal secret-agent platypus-like silhouette nod

These are intentionally minimal original shapes, not copied character art or logos. They should appear briefly and occasionally, behave like hidden visual jokes, and never interfere with reading the name.

### Motion

- slow horizontal highlight sweep across the name
- tiny perspective/offset drift in secondary outlines
- subtle pulse in operator lights
- rare cameo pop-ups using keyframe timing so they are not constantly visible
- all key text stays static enough to read instantly

## 3. Activity World

Create a new self-hosted `assets/activity-world.svg` immediately below Dave.

### Data source

The terrain must be generated from the real contribution-grid data produced for the profile's existing contribution animation. The generator parses the contribution grid classes/positions and maps contribution intensity to terrain height.

The checked-in SVG is regenerated by GitHub Actions alongside the existing telemetry/3D contribution assets.

### Terrain rendering

The scene is a dark pseudo-3D/isometric platform field rather than a raw GitHub heatmap.

- each contribution cell becomes a visible terrain block/column
- zero/low contributions are short platforms; stronger days become taller columns
- columns use depth faces and top faces so the landscape reads as 3D
- the current chronological traversal path is visually clear without requiring labels on every cell
- colors retain a contribution-intensity signal while matching the Dave palette
- the scene includes restrained stars/grid haze and a horizon line so the character reads as moving through a world rather than over a chart

### Original traversal mascot: BRICK

BRICK is an original cyber-gel runner designed for this profile.

Visual traits:

- compact but exaggeratedly muscular upper body
- broad shoulders and oversized forearms
- short powerful legs
- semi-gel body with armored shoulder/chest plates
- cyan/violet edge lighting
- narrow luminous visor/eyes
- expressive squash/stretch silhouette
- deliberately distinctive and readable at small scale

The character is not based on or copied from an existing mascot.

### Locomotion states

The generator classifies adjacent terrain transitions and emits the animation choreography.

1. **Jump** — normal/default traversal. BRICK follows an arc from one column top to the next.
2. **Climb/pull-up** — for a small upward step that is too close to justify a full jump. BRICK reaches the lip, hangs briefly, pulls himself up, and compresses at the top.
3. **Sprint** — when the path encounters a flat run of at least 3 consecutive equal-height columns. BRICK lowers posture and traverses the run faster with short foot/body recoil rather than hopping.
4. **Turnaround** — at either end of the traversal, BRICK skids/compresses, flips facing direction, and traverses back through the same terrain.

The complete loop is bidirectional: beginning → end → beginning, indefinitely.

### Column physical reaction

When BRICK lands or climbs onto a column:

- the target column compresses slightly downward
- rebounds a little above its actual height
- settles back to the exact source-derived contribution height
- its nearest neighbors receive a much smaller secondary wobble

The response should read like dense cyber-slime/gelatin rather than rubber toys.

On a climb state, the target column receives a subtle shake during the pull-up, then settles.

### Motion quality

- movement must use easing/spline timing rather than linear teleporting
- jump arcs get anticipation → launch → airborne stretch → impact squash → recovery
- sprint transitions visibly differ from jump cadence
- the loop should be long enough to avoid feeling repetitive
- no full-screen shaking, strobing, rapid flashes, or motion that damages readability

## 5. Generator architecture

Add a focused generator script rather than hand-authoring hundreds of terrain columns and animation keyframes.

Proposed files:

- `scripts/generate_activity_world.py` — contribution parsing, terrain derivation, locomotion classification, SVG generation
- `assets/activity-world.svg` — generated, checked-in output used by README
- `assets/identity-headboard.svg` — hand-authored/static source-controlled SVG animation

The generator accepts an input contribution SVG file path and output path via environment variables/CLI defaults so it is testable locally and in Actions.

## 6. Workflow integration

Extend `.github/workflows/profile-assets.yml` without broadening write scope.

- third-party contribution/3D generation stays in a read-only generation job
- `generate_activity_world.py` runs after the relevant contribution source is available
- generated `assets/activity-world.svg` is packaged with the other generated profile assets
- publisher stages only known generated paths
- no `git add -A`
- no mutable `@latest` action references
- write permission remains isolated to publish jobs

If the current snake generator remains the easiest authoritative source of contribution-cell classes, its generated dark SVG can be passed to the Activity World generator through an artifact or generated in the same read-only job. The final public README does not need to display the snake.

## 7. Validation

Extend the permanent profile validator to assert:

- README places headboard before Dave and Activity World immediately after Dave
- `assets/identity-headboard.svg` and `assets/activity-world.svg` exist
- all displayed local SVGs parse as XML
- no displayed SVG contains `<script` or `javascript:`
- all README images have useful alt text
- Activity World contains the expected BRICK/terrain animation markers
- Activity World contains both forward and reverse traversal timing markers
- Activity World contains sprint, jump, climb, and settle choreography markers when the current contribution terrain supports those states
- workflow write scope remains narrow and actions remain pinned
- README does not regress to fragile external stat-card providers
- README does not expose private Dave repo name or personal Gmail address

## 8. Security model

Threat surface is small but not zero because generated SVG is displayed publicly and Actions mutate the profile repository.

Controls:

- contribution input is treated as untrusted generated text; parser extracts only expected numeric geometry/class information and never evaluates code
- SVG output is generated from hard-coded templates plus escaped/numeric data only
- no foreign `<script>`, event handler, or external resource URL from the input is copied into output
- third-party Actions are pinned to immutable commit SHAs
- generation jobs are read-only
- publishing jobs stage exact paths only
- validator scans displayed generated SVGs for executable URL/script primitives

- the profile opens with the new readable animated headboard

- the rest of the page remains polished and readable below the new hero sequence
- validation workflow passes on the PR tree
- security diff review finds no unresolved reportable issue
- merge completes
- first post-merge generation/publish workflows complete successfully
- final live `main` is revalidated after generated assets land
